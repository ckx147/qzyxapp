# 儿童萌趣益智游戏乐园 - 微信云开发部署前清单

标签：#微信云开发 #部署清单 #集合索引 #权限

更新时间：2026-06-10

## 目标

在真正进入微信开发者工具或云开发控制台前，先确认数据库集合、索引、权限和云函数部署顺序。当前项目已有本地可测试云函数草案，但尚未部署到微信云环境。

## 当前云函数草案状态

已完成本地测试但未部署：

- `loginOrCreateUser`
- `getHomeState`
- `saveGameState`
- `getLeaderboard`

当前云端 MVP 链路：

```text
loginOrCreateUser -> getHomeState -> saveGameState -> getLeaderboard
```

## 必建集合

### `users`

用途：用户基础档案。

字段：`_id`、`_openid`、`nickname`、`avatarId`、`status`、`createdAt`、`updatedAt`、`lastLoginAt`。

索引：
- `_openid` 唯一索引
- `updatedAt` 普通索引

权限：
- 客户端不直接读写。
- 仅云函数读写。
- `_openid` 永不返回前端。

### `user_stats`

用途：用户聚合状态、积分、记录、排行榜来源。

字段：`_id`、`userId`、`_openid`、`pointsBalance`、`feedHappiness`、`records`、`checkInStreak`、`lastCheckInDate`、`createdAt`、`updatedAt`。

索引：
- `_openid` 唯一索引
- `userId` 唯一索引
- `pointsBalance` 降序索引
- `updatedAt` 普通索引

权限：
- 客户端不直接读写。
- 排行榜只能通过 `getLeaderboard` 返回公开字段。

### `achievements`

用途：用户成就状态。

字段：`_id`、`userId`、`_openid`、`achievementId`、`tier`、`targetValue`、`progress`、`unlocked`、`unlockedAt`、`rewardsClaimed`、`createdAt`、`updatedAt`。

索引：
- `_openid + achievementId` 唯一索引
- `userId + achievementId` 唯一索引
- `userId` 普通索引

权限：
- 客户端不直接读写。
- 由 `loginOrCreateUser` 初始化，`saveGameState` 草案白名单更新。

### `checkins`

用途：签到状态和后续签到记录。

当前草案字段：`_id`、`userId`、`_openid`、`lastCheckInDate`、`streak`、`unlockedItems`、`createdAt`、`updatedAt`。

后续正式签到流水字段可扩展：`date`、`streakAfter`、`rewardPoints`、`rewardItemName`、`rewardItemCount`。

索引：
- `_openid` 唯一索引
- `userId` 普通索引
- `_openid + date` 唯一索引，等 `claimDailyCheckin` 独立云函数落地后再启用

权限：
- 客户端不直接读写。
- 日期口径后续统一为 Asia/Shanghai。

### `inventory_items`

用途：背包道具数量。

字段：`_id`、`userId`、`_openid`、`itemName`、`count`、`createdAt`、`updatedAt`。

索引：
- `_openid + itemName` 唯一索引
- `userId + itemName` 唯一索引
- `userId` 普通索引

权限：
- 客户端不直接读写。
- 后续购买和喂养应改为独立云函数，避免客户端直接决定库存变化。

### `point_transactions`

用途：积分流水审计。MVP 草案中先预留，正式积分结算云函数落地时启用。

字段：`_id`、`userId`、`_openid`、`amount`、`balanceAfter`、`reason`、`sourceType`、`sourceId`、`clientRequestId`、`createdAt`。

索引：
- `_openid + createdAt` 普通索引
- `_openid + clientRequestId` 唯一索引
- `sourceType + createdAt` 普通索引

权限：
- 客户端不直接读写。
- 所有积分变化必须由服务端计算后写入。

## 可选集合

### `leaderboard_snapshots`

用途：排行榜快照或缓存。

当前建议：
- 早期先由 `getLeaderboard` 实时读取 `user_stats.pointsBalance`。
- 用户量上来后再启用快照。

字段草案：`_id`、`scope`、`period`、`items`、`generatedAt`。

索引：
- `scope + period`
- `generatedAt`

权限：
- 即使启用快照，也只保存公开展示字段。

## 云函数部署顺序

1. 在本地运行 `npm.cmd run test:cloudfunctions`。
2. 在本地运行 `npm.cmd run test:data-service`。
3. 创建云开发环境。
4. 创建集合和索引。
5. 设置集合权限为“仅云函数可读写”或等价最小权限。
6. 部署 `loginOrCreateUser`。
7. 部署 `getHomeState`。
8. 部署 `saveGameState`。
9. 部署 `getLeaderboard`。
10. 用微信开发者工具验证 `_openid` 是否可用。
11. 手动调用 `loginOrCreateUser`，确认创建 `users`、`user_stats`、`achievements`、`inventory_items`。
12. 手动调用 `getHomeState`，确认返回前端 `GameState` 形状，且不包含 `_openid`。
13. 手动调用 `saveGameState`，确认只写白名单字段，不写客户端排行榜。
14. 手动调用 `getLeaderboard`，确认按 `user_stats.pointsBalance` 排序，且只返回公开字段。

## 权限草案

- 客户端不直接读写核心集合。
- 核心数据全部通过云函数访问。
- `_openid` 只在云函数内部使用，不返回前端。
- 排行榜只返回 `id`、`nickname`、`avatarId`、`points`、`isCurrentUser`。
- 客户端传入的 `profile.id` 只能用于校验当前用户，不可用于写入其他用户数据。
- 客户端传入的排行榜、积分排名、`_openid`、未知字段一律不信任。

## 部署后冒烟测试

1. 新用户首次进入：`loginOrCreateUser` 成功创建默认档案。
2. 首页读取：`getHomeState` 返回 `profile`、`achievements`、`checkIn`、`leaderboard`。
3. 保存状态：修改积分或背包后调用 `saveGameState`，数据库只变化白名单字段。
4. 排行榜读取：`getLeaderboard` 排序来自 `user_stats.pointsBalance`，不是客户端传入数据。
5. 安全负例：模拟传入他人 `profile.id`，`saveGameState` 返回 `FORBIDDEN_USER_MISMATCH`。
6. 安全负例：模拟缺少 `_openid`，四个云函数都返回 `UNAUTHENTICATED`。

## 暂不做

- 暂不把前端 `activeGameDataPort` 切到云端；目前已有 `VITE_USE_WECHAT_CLOUD=true` 草案开关，但需等真实云函数部署和冒烟通过后再打开。
- 暂不允许客户端直连数据库。
- 暂不开放自定义真实头像上传。
- 暂不实现公开全服儿童排行榜，正式上线前先评估家庭/班级/好友范围。
