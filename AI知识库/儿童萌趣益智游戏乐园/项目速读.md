## 核心结论

- 玩法和儿童向包装已经比较完整。
- 状态全在前端，本地 `localStorage` 保存。
- 排行榜是本地模拟，不是云端数据。
- 小程序上线前需要处理身份、云存储、排行榜和合规。
- 当前最大代码风险是积分重复发放。

## 最大风险

### P0：积分重复发放

游戏结算时重复加分，影响积分、排行榜、商店经济、成就反馈。

修复原则：

- 只有 `App.tsx` 的 `handlePointsChange` 可以改 `profile.points`。
- 子游戏组件只更新游戏记录和成就，不直接改积分。

### P1：不能直接当小程序跑

不可直接迁移的 Web API：

- `localStorage`
- `window`
- `document`
- `new Image`
- `AudioContext`
- React DOM

## 下一步建议

1. 修积分重复发放。
2. 安装依赖并验证 `npm run lint`、`npm run build`。
3. 清理 AI Studio 模板残留。
4. 决定小程序路线。
5. 若要上线，设计云端数据模型。
