# 儿童萌趣益智游戏乐园 - 微信云开发落地清单

标签：#微信云开发 #云函数 #数据落地

## 目标

把 `数据模型草案.md` 落成可执行的微信云开发方案。当前仍是规划文档，尚未创建云环境或改 APP 源码。

## MVP 集合

### `users`

用途：用户基础档案。

字段：

- `_id`
- `_openid`
- `nickname`
- `avatarId`
- `createdAt`
- `updatedAt`
- `lastLoginAt`
- `status`

索引：

- `_openid` 唯一。
- `updatedAt` 普通索引。

权限：

- 客户端只能读写自己的非敏感展示字段。
- `_openid` 不暴露给客户端业务逻辑。

### `user_stats`

用途：首页、个人页、排行榜读取的聚合状态。

字段：

- `_id`
- `userId`
- `_openid`
- `pointsBalance`
- `feedHappiness`
- `records`
- `checkInStreak`
- `lastCheckInDate`
- `updatedAt`

索引：

- `_openid` 唯一。
- `pointsBalance` 降序，用于排行榜。
- `updatedAt` 普通索引。

权限：

- 用户只能读自己的完整统计。
- 排行榜只返回昵称、头像、积分等公开展示字段。

### `point_transactions`

用途：积分流水，所有加减积分必须写入。

字段：

- `_id`
- `userId`
- `_openid`
- `amount`
- `balanceAfter`
- `reason`
- `sourceType`
- `sourceId`
- `clientRequestId`
- `createdAt`

索引：

- `_openid + createdAt`
- `_openid + clientRequestId` 唯一。
- `sourceType + createdAt`

规则：

- 扣分后余额不能小于 0。
- 同一个 `clientRequestId` 只能成功一次。
- 服务端计算最终 `amount`，不要完全信任客户端传值。

### `achievements`

用途：用户成就状态。

字段：

- `_id`
- `userId`
- `_openid`
- `achievementId`
- `tier`
- `targetValue`
- `progress`
- `unlocked`
- `unlockedAt`
- `rewardsClaimed`
- `updatedAt`

索引：

- `_openid + achievementId` 唯一。

### `checkins`

用途：每日打卡记录。

字段：

- `_id`
- `userId`
- `_openid`
- `date`
- `streakAfter`
- `rewardPoints`
- `rewardItemName`
- `rewardItemCount`
- `createdAt`

索引：

- `_openid + date` 唯一。

### `inventory_items`

用途：零食背包数量。

字段：

- `_id`
- `userId`
- `_openid`
- `itemName`
- `count`
- `updatedAt`

索引：

- `_openid + itemName` 唯一。

## 可后置集合

- `game_records`：如果 MVP 只同步最好成绩，可后置；如果要审计游戏积分，建议提前。
- `leaderboard_snapshots`：早期可实时查 `user_stats.pointsBalance`，有规模后再做快照。
- `inventory_transactions`：如果需要完整审计零食来源，再补。

## 云函数/API

### `loginOrCreateUser`

职责：

- 通过微信登录创建或读取用户。
- 初始化 `users`、`user_stats`、默认成就和背包。
- 返回首页所需最小状态。

### `getHomeState`

职责：

- 返回用户档案、积分、宠物好感、打卡状态、背包、成就摘要。
- 不返回积分流水全量数据。

### `claimDailyCheckin`

职责：

- 校验今天是否已打卡。
- 写入 `checkins`。
- 写入 `point_transactions`。
- 更新 `user_stats.checkInStreak`、`lastCheckInDate`、`pointsBalance`。

幂等：

- 使用 `_openid + date` 防重复。

### `submitGameResult`

职责：

- 接收游戏类型、模式、结果、耗时、步数等。
- 基于服务端规则计算积分变化。
- 更新最好记录、成就进度和积分流水。

幂等：

- 使用 `clientRequestId` 防重复提交。
- 对异常高频提交做限制。

### `purchaseFood`

职责：

- 校验余额是否足够。
- 扣积分并写积分流水。
- 增加 `inventory_items` 数量。

### `feedCompanion`

职责：

- 扣除背包物品。
- 增加宠物好感度。
- 更新 `user_stats.feedHappiness`。

### `claimAchievementReward`

职责：

- 校验成就是否达成且未领取。
- 写积分流水。
- 标记 `rewardsClaimed`。

### `getLeaderboard`

职责：

- 从 `user_stats.pointsBalance` 读取前 N 名。
- 只返回昵称、头像 id、积分和排名。
- 不返回 openid 或内部 userId。

## 权限与隐私

- 默认不存真实姓名、手机号、真实头像原图。
- 昵称和头像优先使用预设值。
- 正式上线前补齐隐私政策、家长授权、数据删除和数据导出说明。
- 云函数中统一校验 `_openid`，不要让客户端传入任意 `userId` 修改别人数据。
