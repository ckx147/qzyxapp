# 儿童萌趣益智游戏乐园 - 本地与云端数据边界

标签：#数据迁移 #微信云开发 #低token #交接

更新时间：2026-06-09

## 当前结论

当前 Web 原型仍使用本地 `localStorage`，但源码已拆出两级迁移入口：

- `src/utils/gameStorage.ts`：最底层本地存储适配器，负责字符串/JSON 读写。
- `src/utils/gameDataService.ts`：业务数据服务层，暴露接近云端的 `loadGameState()`、`saveGameState()`、`syncLeaderboard()`。
- `src/utils/leaderboardService.ts`：排行榜独立服务，当前仍读写本地榜单，后续可替换为云数据库查询。

## 本地数据

这些数据适合继续留在设备本地，迁移到微信小程序后可映射到 `wx.getStorageSync` / `wx.setStorageSync`：

- 音频设置：背景音乐开关、音效开关、旧版静音兼容值。
- 临时 UI 设置：只影响当前设备体验、不需要跨设备同步的偏好。
- 临时缓存：图片预览、自定义头像本地缓存等非核心进度数据。

## 云端数据

这些数据正式小程序化后应进入云端，支持跨设备、排行榜、审计和数据删除：

- 用户档案：用户 id、昵称、头像 id、创建时间、最近登录时间。
- 积分：当前积分余额和积分流水。
- 成就：成就进度、等级、解锁时间、奖励领取状态。
- 排行榜：从云端聚合或 `user_stats.pointsBalance` 查询，客户端不应直接决定排名。
- 签到：每日签到日期、连续天数、签到奖励记录。
- 游戏记录：四个游戏的最好成绩、胜负/平局、通关统计。
- 背包：零食库存和关键消耗记录。

## 迁移入口

后续接微信云开发时，优先按这个顺序替换：

1. `gameDataService.ts`
   - 把 `loadGameState()` 映射到 `loginOrCreateUser` + `getHomeState`。
   - 把 `saveGameState()` 拆成更细的云函数调用，例如 `submitGameResult`、`claimDailyCheckin`、`purchaseFood`。
   - 把 `syncLeaderboard()` 改为读取云端排行榜。

2. `leaderboardService.ts`
   - 将 `loadLocalLeaderboard()` / `saveLocalLeaderboard()` 替换为云数据库查询或云函数 `getLeaderboard`。
   - 保留 `buildLeaderboardWithUser()` 作为前端展示兜底，但最终排名以服务端为准。

3. `gameStorage.ts`
   - 仅保留本地偏好和临时缓存。
   - 不再保存积分、成就、签到、排行榜等核心进度。

## 不要做

- 不要让组件直接访问 `localStorage`、`wx.getStorageSync` 或云数据库。
- 不要把排行榜排序/读写逻辑重新塞回 `gameHelpers.ts`。
- 不要让客户端直接提交最终排行榜名次，只提交可校验的游戏结果或积分事件。
