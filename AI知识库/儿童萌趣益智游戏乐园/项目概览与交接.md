## 已发现的关键问题

### P0：积分重复发放

多个游戏结算时既调用 `onPointsChange(...)`，又直接在 `setProfile` 内给 `points` 加分，导致积分翻倍或重复入账。

已确认位置：

- `src/components/KlotskiGame.tsx`：`onPointsChange(rewardPoints, ...)` 后又 `points: prev.points + rewardPoints`
- `src/components/SchulteGame.tsx`：`onPointsChange(baseReward, ...)` 后又 `points: prev.points + baseReward`
- `src/components/BombGame.tsx`：胜利和惩罚奖励都存在类似重复加分
- `src/components/GomokuGame.tsx`：先更新 `updatedPoints`，又通过 `onPointsChange(diff, ...)` 再加一次

建议修复原则：积分只允许通过 `App.tsx` 中的统一 `handlePointsChange` 修改；游戏组件只更新记录、背包、成就等非积分状态。

### P1：当前不是微信小程序工程

项目依赖 Web API，不能直接作为微信小程序运行：

- `localStorage`
- `window`
- `document.createElement('canvas')`
- `new Image()`
- `AudioContext`
- Vite/React DOM 渲染

迁移方向可选：

- 用 Taro/uni-app 重构成小程序。
- 保留 React Web 版，微信小程序中用 WebView 承载。
- 重写为原生微信小程序。

### P1：本地数据无法跨设备

用户档案、排行榜、成就、打卡都存在本地 `localStorage`，换设备或清缓存会丢失。

如果要上线，需要考虑：

- 微信登录身份
- 云开发数据库或自有后端
- 云端排行榜
- 成就和积分服务端校验

### P2：AI Studio 模板残留

- `package.json` 项目名仍为 `react-example`
- `README.md` 是 Google AI Studio 默认说明
- `.env.example` 要求 `GEMINI_API_KEY`
- `metadata.json` 声明 `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API`
- 但当前源码未看到实际 Gemini 调用

后续要么删除模板痕迹，要么明确设计 AI 功能。
